# 编剧 Agent 方法论

这个文件夹只做一件事：调试"主 agent"——它看到一张展品照片，最后交出一份可以直接拿去生成视频的剧本。
产品代码（服务器、界面、调用 fal 的流水线）由其他人负责，这里不碰。

> 剧本功底决定效果上限。Seedance 能画出来的东西很多，但它只会照着我们写的去画。
> 主要能力来自模型的**多模态理解**（看照片、看参考图），加上少量**准备好的文字资料**，再由提示词和 harness 约束。

---

## 1. 什么算"好"的展品视频

| 维度 | 好的样子 | 常见的坏样子 |
| --- | --- | --- |
| 钩子 | 前 2–3 秒就让人想看下去：一个画面、一个问题、一个反差 | "Hello, I am a blue whale skeleton…" |
| 观众视角 | 回答站在展品前的人心里真正的疑问（它怎么来的？为什么在这？它活着时什么样？） | 照念展牌、罗列数字 |
| 一个核心 | 一条片子只讲一件事、一种情绪 | 想把所有事实都塞进去 |
| 声画对位 | 台词补充画面看不到的东西（意义、过去、缺失、感受） | 画面是沙洲，台词也说"沙洲" |
| 真实 | 每一句事实都能追到资料包里的来源；不加资料没有的限定词 | 编年份、自己算数（"38 年"）、"孤独地死去" |
| 能画出来 | 每个镜头一个运镜、一个动作；一个镜头只出现一种主体状态 | 画面里写字、骨架和活体同框、变形 |
| 长度匹配内容 | 内容少就 15 秒，内容多才 30 秒；台词有呼吸感 | 为凑时长注水，或台词塞满没有停顿 |
| 收尾 | 最后一句完成核心想法，画面让观众抬头对照实物 | 口号、说教、"让我们保护地球" |

## 2. Agent 的工作分解（v1.5）

```
照片 ─► S0 识别 ─► S0b 联网调研 ─► S1 消化资料 ─► S1b 参考图规划 ─┬─► [图像生成：照片 + 提示词，可与下面并行]
        （看图）   （web_search +      （资料包 +        （看图）        │
                    web_fetch 工具；   调研结果）                       └─► S2 构思 ─► S3 写剧本 ⇄ S4 审稿 ─► final.json
                    一次输出 5–10 个                                         （最多 3 稿，计时由代码自动微调，取最好的一稿）
                    关键词）
final.json = 图像生成任务 + Seedance 请求（@ImageN 对应生成好的图片）+ 字幕 + 声音 + 预估费用
```

| 顺序 | 你描述的步骤 | 对应阶段 | 产出 |
| --- | --- | --- | --- |
| 1 | 单张图片理解、识别 | S0 | 认出展品，照片里看得到什么 |
| 2 | 调用 search 工具 | S0b | 来源、逐条带 URL 的发现、冲突、没找到的；**URL 必须是工具真正返回过的**（代码检查） |
| 3 | 一次性输出多个关键词 | 单独的侧边请求 `keyword_batch` | 识别后、搜索后各一次，后台线程，核心 agent 不等它；一次输出 5–10 个，必须照抄材料原词（代码检查） |
| 4 | 文生图开始出图 | S1b → `image_jobs.json` | 每张参考图 = 观众照片（初始图，代码写死）+ S1b 写好的文字提示词（含视角和禁止项）；模型、参数全部写死在 `images.py`，LLM 只写提示词；发出 `image_jobs_ready` 事件 |
| 5 | 继续打磨剧本、规划 | S1 → S2 → S3 ⇄ S4 | 核心想法、构思、剧本，在出图的同时进行 |
| 6 | 最终 prompt + 多角度图片喂给视频模型 | `final.json` | Seedance 请求，`image_urls` 写成 `<job:id>` / `<existing:id>` |

调研结果补充而不是替代准备好的资料包：两者一致时引用资料包，冲突时以馆方页面为准并列为冲突。
没有资料包的展品可以只靠调研（目前 `run.py` 仍要求有 `knowledge/<id>/`，这一点还没做）。

**照片和参考图在每个阶段都可见**，不只是 S0。写剧本的人看得到 Hope 实际长什么样、观众站在哪。

| 阶段 | 输入 | 输出 | 主要调试点 |
| --- | --- | --- | --- |
| S0 识别 | 照片 + 已准备的展品清单 | 先自由识别（"这是什么"），再匹配资料包；照片里看得到什么；观众可能好奇什么 | 认错时宁可不匹配 |
| S1 消化资料 | 资料包 + 照片 | 事实（带来源）、冲突说法、观众的问题、故事素材、情绪核心、**15 还是 30 秒** | 时长判断；有没有混入资料外的推断 |
| S1b 参考图规划 | 素材单 + 照片 + 已有参考图 | 固定描述（subject_lock / living_form_lock）+ 参考图提示词：生前复原、角色设定图、现状干净视图、细节 | 参考图不能带文字标签、人、玻璃 |
| S2 构思 | 以上全部 | 3 个"引擎"不同的构思（反转 / 决定性瞬间 / 从眼前回溯 / 对比 / 直接对话 / 被忽略的细节），选一个 | 是否真的不同；钩子和结尾台词是否已经合规 |
| S3 写剧本 | 以上 + 选中的构思 | 结构化剧本（见第 4 节）；修改时**在上一稿上改**，只改被指出的地方 | 声画对位；逐句计时；每句标注类型 |
| S4 审稿 | 剧本 + 构思 + 资料包原文 + **渲染好的 Seedance 请求** + 照片 + 上一轮审稿 | 逐句事实核对 → 问题（blocking / polish）→ 10 项打分 | 不自相矛盾；能否发现模板问题 |

**是否通过由代码决定，不由审稿模型决定**：没有硬检查问题、没有 blocking、truth = 5、所有分数 ≥ 4。
通过但还有 polish 意见时，再改一轮。最多 3 稿，交付其中最好的一稿，状态写进报告：
`PASS` / `PASS_WITH_OPEN_POLISH` / `NEEDS_HUMAN`。

## 3. 时长与台词密度

- 语速按 **2.5 个口语词/秒** 计。"1891" 读作 eighteen ninety-one，算 3 个词（`checks.spoken_words`）。
- 片头至少 0.8 秒只有画面和声音；每段最后一句至少在段末前 1 秒说完；句与句不重叠。
- 15 秒一段约 25–30 个口语词，30 秒片约 50–60 个，少一些往往更好。
- 时长由内容决定：可用事实少、故事只有一个点 → 15 秒；有完整的起承转合 → 30 秒。
- demo 总长约 2 分钟：例如 2 个 30 秒 + 4 个 15 秒。

## 4. 剧本的结构（agent 的最终产物）

剧本是**结构化数据**；`seedance.py` 再把它渲染成真正的 fal 请求。把"写什么"（agent 的判断）和"怎么写给 Seedance"（模板）
分开，换写法时不用重调 agent。第一轮里审稿员两次指出的问题其实是模板的 bug，正是这种分离让它暴露出来。

```
Script
├─ title, logline, duration_s (15|30), style (realistic|stylized), narrator_presence (voiceover|on_screen)
├─ voice            一句固定的声音描述，两段里一字不差地重复（Seedance 2.0 两次生成之间声音不连续）
├─ narrator_attitude, subject_lock, living_form_lock
├─ assets[]         id、existing|generate、depicts (exhibit_now|living_form|environment|detail)、提示词
├─ segments[]       每段 ≤ 15 秒 = 一次生成
│   ├─ setting, ref_assets[] (≤4, 上传顺序 = @Image1..)
│   ├─ shots[]      t_start, t_end, refs[], framing, camera(一个运镜), action(一个动作), visual(≤25 词)
│   ├─ narration[]  t_start, text(口语写法), kind (fact|visible|voice), fact_ids[]
│   ├─ audio        ambience, sfx[], music（两段同一种音乐风格；段尾能干净收住）
│   └─ end_frame    段尾接近静止的画面，方便硬切
└─ subtitles[]      纯英文，与旁白逐字一致
```

## 5. Seedance 与参考图（第一轮调研，已交叉核实）

详细资料见 `research/round1_raw.json`。

- 用 `bytedance/seedance-2.0/reference-to-video`：时长 "4"–"15"（字符串），最多 9 张参考图，提示词里用 `@Image1…` 指代（按上传顺序），`generate_audio` 默认开启且不额外收费。
- 要念的台词放在英文双引号里；多镜头用 "Cut to"；明确写出要什么声音，不要音乐就写 "no music"。
- 2.0 没有 seed，两段之间的声音、画面不保证连续 → 声音描述一字不差地重复，两段之间用硬切。
- **价格**：标准档 720p 约 $0.30/秒，即 15 秒约 $4.5，30 秒约 $9。草稿用 mini 档 480p。
- 参考图：nano-banana-pro/edit 把观众照片清理成干净的正视图（$0.15），qwen-image-edit multiple-angles 生成侧视等角度（约 $0.035），seedream v4.5 edit 作为备选。
- 参考图模式参照 ChatGPT 的流程：**生前复原图 + 当时环境 → 角色设定图（正面、侧面、表情）→ 风格（写实 / 轻动漫）**。
  设定图常带文字标签，送进 Seedance 前必须裁成不带字的图（`checks.notes` 会提醒）。

## 5b. 进度关键词（给产品做实时进度展示）

关键词是**单独的侧边请求**（`prompts/keywords.md`，effort low，模型可用 `KEYWORD_MODEL` 单独指定），核心 agent 只写脚本和提示词。
- 识别（S0）之后和搜索（S0b）之后各发一次，在后台线程里跑，核心流程不等待；失败也不影响成片。
- 一次输出 5–10 个关键词（名称、年代/朝代、日期、地点、人物、材质、尺寸、物种），依据是来源 URL、photo 或 pack。
- `checks.keywords`：每个关键词的每个词都必须出现在给它的材料里（防止改写、截断改变原意、引错来源）。
- 事件写进 `runs/<run>/events.jsonl`：`{"type": "keywords_batch", "label": "research", "keywords": [...], "flags": [...]}`，
  以及 `search` / `source` / `image_jobs_ready` / `retry` 等进度事件，`t_run` 为从运行开始算的秒数。

## 5c. 手动输入

`uv run python run.py hope --user-input "选15s"`：原样以 `User input: …` 追加到 S1–S4 的输入末尾（不加给识别和搜索）。
S1 定长度时以它为准；S2/S3 在不违反事实规则的前提下照做。长度本身不再检查，30 秒可以。
实测：同一件展品，不加输入得到 15 秒，加 "选30s" 得到 30 秒，两版都通过。

## 6. Harness：怎么调

### 原则
1. **每次运行都留完整档案**：完整提示词（带 sha）、看到的图片（哈希）、思考摘要、原始输出、检查结果、反馈、费用。
2. **一次只改一件事**，在全部测试展品上重跑，和上一版并排比较；有随机性，比较时用 `--sample N` 多抽几次。
3. **提示词是独立文件**（`prompts/<阶段>.md`），旧版本放 `prompts/archive/`；A/B 用 `--variant s3=名字`。
4. **阶段自动复用缓存**：只改了 S3，S0–S2 直接用缓存，不花钱。
5. **回归集**：每个测试展品有 `expect.json`（期望时长、禁止出现的说法），检查代码自动对照。
6. **审稿员不是裁判**：通过与否由代码判；对比提示词版本时用独立的盲评，不用 S4 自己的分数。

### 测试展品
| id | 内容量 | 设下的陷阱 |
| --- | --- | --- |
| hope | 丰富 → 30 秒 | 骨头数、姿态无来源；Dippy 1979–2017 诱导算出"38 年"；资料里没有死亡、孤独、改名 |
| sophie | 丰富 → 30 秒 | 骨头数冲突（over 300 vs 360）；完整度百分比无来源；"美国以外唯一"只在 2014 年成立；性别未知 |
| sequoia | 单薄 → 15 秒 | 砍伐年份冲突（1893 vs 1891）；直径无来源；森林数据容易跑题 |

### 命令
```
uv run python run.py hope                 # 用 meta.json 里的测试照片
uv run python run.py all                  # 全部展品
uv run python run.py hope --variant s3=x  # 用 prompts/s3_script.x.md
uv run python run.py hope --sample 2      # 同样输入的另一次独立抽样
```

## 7. 还没定的问题

- **预算**：2 分钟 demo 最终渲染约 $18–27（720p 标准档），加上草稿和重试。需要团队拍板。
- **旁白由谁发声**：Seedance 原生声音（两段可能变声）还是外部 TTS 全片一条？现在剧本两种都支持（`narrator_presence` + `voice`）。
- **画幅**：demo 投屏用 16:9，手机观看用 9:16；`SEEDANCE_ASPECT` 可切换。
- 没有资料包的展品：可以让 S1 用 Claude 联网搜索现查，带出处。demo 可以先只用准备好的资料包。
- 选项功能（科普强度、时长、卡通/写实）优先级低；`style` 已经是剧本字段，后面再接到用户选择上。
