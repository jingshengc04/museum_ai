# 提示词总览

每个提示词的完整原文在 `prompts/` 下，这里是每个提示词"要求模型做什么"的总结。

## 精简流程（`lean.py`）：3 次主调用 + 关键词旁路

```
照片 → ① 看图识别 → ② 联网搜索 → ③ 一次写完 → 两张参考图 + 一个视频请求 → 视频模型
            └ 关键词 ┘      └ 关键词 ┘
```

### ① 看图识别　`prompts/s0_identify.md`

- **输入**：游客照片。
- **输出**：文物名称、所在博物馆、把握程度、照片里实际拍到了什么。
- **要求**
  - 只凭照片判断这是什么；认出具体展品就说是哪一件。
  - 认不准就说认不准，认错比不认更糟。
  - 描述照片的视角：拍到哪一部分、角度、远近、光线、有没有人。影片从这个视角开场。

### ② 联网搜索　`prompts/s0b_research.md`

- **输入**：照片和识别结果。
- **工具**：Claude API 自带的搜索和网页读取，最多搜 5 次、读 4 个网页。
- **输出**：一条条事实，每条带来源网址和原文引用。
- **要求**
  - 按重要性找四类事实：
    1. 它是什么、多老；
    2. 做什么用、对当时的人意味着什么（用途、仪式、信仰、象征）；
    3. 经历过的大事（出土、损毁、修复、搬迁）；
    4. 现在在哪、今天为什么重要。
  - 第 2、3 类各至少专门搜一次。尺寸、材料、工艺排在后面。
  - 优先找收藏机构自己的网页，其次是其他博物馆、大学、有出处的百科、主流媒体。
  - 每条事实必须照抄原文的说法和限定词，不凭记忆补充，不把两个网页拼成新结论，不引用社交媒体。
- **代码检查**：来源网址必须是搜索工具真实返回过的；事实里的数字必须出现在引文里。不满足的直接丢弃。

### ③ 一次写完　`prompts/lean_write.md`

- **输入**：照片、编号的事实清单、用户附加输入（如"15s"）。
- **输出**：标题、时长、台词（带时间和出处编号）、分时间段的画面描述、角色外观一句话、声音描述、音效清单。
- **故事**：文物用第一人称自我介绍，按顺序讲完并收尾：
  1. 我是谁（是什么、多老）；
  2. 我是干什么用的、意味着什么；
  3. 我经历了什么（一两件大事）；
  4. 我现在在哪。
  - 哪一段没有事实支持就跳过，不编。
  - 至少三段有事实用 30 秒，否则 15 秒；用户指定了就听用户的。
- **台词**
  - 大白话：像对站在旁边的朋友说话，简单完整的句子、常用词、一句一个意思。
  - 不要谜语、双关、半截句、文绉绉的说法。
  - 讲重要的事，不讲琐事（价格、小事故、发现者或古董商的名字）。工艺细节最多一句。
  - 15 秒 3 句，30 秒 5 到 6 句；每句最多 12 个词；最后一句收尾。
- **真实性**
  - 每句讲事实的台词要标出依据的事实编号，不能说得比事实多。
  - 不加"第一、唯一、最古老"这类原文没有的限定词，不自己算数字（年代区间换算成"三千多年"除外）。
  - 原文说"被称为"的，台词也说"人们叫我们…"。
  - 台词不把画面里的幻想说成真事。
- **画面**
  - 只有一个主角活过来（文物本身或它的一部分），做成风格化 3D 动画角色，靠动作、姿态、眼神表现性格。其余部分不动，结尾文物完整如初。
  - 全片一镜到底、不切镜，按几秒一段的时间段来写，每段一句话，动词在前，带速度和力度。
  - 开场是照片里的真实文物，三秒内出现第一个生命迹象 → 主角挣脱或苏醒，做一个大动作 → 用幻想方式表现每段故事（用途表现为光和运动，损毁表现为碎片悬浮再拼回）→ 主角回到原位变回文物，回到开场角度。
  - 不把真实事件拍成纪实，不出现爆炸、武器、人、文字、标志。
  - 最大的动作那段不说话。
- **声音**：角色的声音是画外音（不对口型），用一句话描述年龄、音色、口音、语速；四五个和动作对应的音效；不要配乐。
- **代码检查**（不过就带着问题重写一次）：句数、每句词数、每句讲事实的台词有出处编号、台词时间不重叠且在结尾前说完、时间段首尾相接、画面里没有人和文字、整个视频请求不超过 430 词。

### 关键词（旁路函数）　`prompts/keywords.md`

- **调用**：`agent.keyword_batch(label, material, run_dir)`，在识别后和搜索后各调一次，后台并行，不阻塞主流程；结果写进 `final.json` 的 `keywords` 和 `events.jsonl`。
- **输入**：一段材料（识别结果或搜索到的事实）。
- **输出**：一组关键词，每个带类别和出处。数量不限。
- **要求**
  - 最重要的排前面：名称 → 朝代或年代 → 材料和重量尺寸 → 用途或文化 → 现在在哪；之后再加其他具体的词（地点、日期、特征）。
  - 每个 1 到 5 个词，必须从材料里原样摘出，不改写、不凑整、不加自己知道的内容。

### 写死在代码里的部分（模型不参与配置）

- **两张参考图**（`lean.py` 里的固定模板，用游客照片加提示词生成）
  - `@Image1` 文物本体：整件、原样、中性光、纯色背景。
  - `@Image2` 角色：按写稿给出的一句外观描述生成，单视图。
  - 两张都固定带"画面中不出现人，包括玻璃和金属表面上的倒影"。
- **视频请求**（`lean.py` 拼装）：参考图说明 → "只有主角活过来" → 画风 → "One continuous take, no cuts" + 各时间段 → 画外音和逐句台词 → 音效 → "不要字幕、文字、人"。
- **模型和参数**：图片 `fal-ai/nano-banana-pro/edit`；视频 Seedance 2.5，一次生成，16:9，分辨率由命令行指定。

## 旧的多阶段流程（`run.py`）：保留作对比

识别和搜索与上面相同，之后是五个阶段：

| 阶段 | 文件 | 做什么 |
|---|---|---|
| 消化资料 | `s1_digest.md` | 把资料整理成逐条事实，剔除琐事，排出故事主线（自我介绍四段式），决定 15 秒或 30 秒 |
| 规划参考图 | `s1b_assets.md` | 规划文物本体图、原位图、角色图等，画面中不出现人 |
| 构思 | `s2_concept.md` | 写三个让文物活起来的方案，按"生命力"选一个 |
| 写稿 | `s3_script.md` | 逐镜头剧本、台词、音效、参考图用法；每段一镜到底 |
| 审稿 | `s4_review.md` | 逐句核对出处，按 12 项打分，提修改意见；最多三轮 |

同一件文物上的对比（四羊方尊，2026-11-15）：

| | 旧流程 | 精简流程 |
|---|---|---|
| 耗时 | 约 12 分钟 | 约 2 分钟 |
| Claude 花费 | 2.91 美元 | 约 0.9 美元 |
| 台词质量 | 大白话、四段齐全 | 大白话、四段齐全 |
| 检查结果 | 需要人工（请求超词数上限） | 通过 |

历史版本的提示词在 `prompts/archive/`。
